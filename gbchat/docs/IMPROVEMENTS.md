## 0. Round 5 — routing, profile, stories, offline & local backup

### 0.1 Fixed in this round

| Finding | Detail | Fix |
| --- | --- | --- |
| **Broken navigation targets** | `/channels/:id` (from every `ChannelCard`), `/profile` (starred tile), `/chat?chatId=…&messageId=…` (pinned + starred "jump to message") and `/settings/notifications` (notification centre) pointed at routes that did not exist — all four landed on the 404 page. | Added `channels/:channelId`, `profile` → `/profile/me`, `settings/:section`, `chats/:chatId` and a legacy `/chat` redirect that maps `chatId`→`chat` and `messageId`→`message`. Deep-linked messages now scroll into view and flash a highlight ring. |
| **A whole component was unreachable** | `ChannelFeed.jsx` existed but no route rendered it, and it crashed on `data.posts` when the API returned an array. | New `ChannelDetail.jsx` at `/channels/:channelId`: header, subscribe toggle, post composer, real like counts, share sheet, empty/loading states. |
| **Scroll position leaked between routes** | Router kept the previous pane's scroll offset; opening a profile from a scrolled chat list landed mid-page. | `ScrollToTop` resets the window *and* inner scroll containers on pathname change (query-only changes such as `?chat=` keep their position). |
| **Duplicate route registration** | `PUT /api/groups/:id` was registered twice in `groupRoutes.js`; the first handler always won and the second was dead code. | Duplicate removed (`duplicate routes: 0`). |
| **Endpoint checker false positives** | Query strings (`/users/search?q=…`) were treated as part of the path, so a perfectly valid call showed up as "unmatched". | `check-endpoints.mjs` and `audit-endpoints.mjs` strip the query string before normalising. |
| **Profile had nowhere to put real detail** | Only name, handle, bio, phone, website, location. | Added `jobTitle` + `timezone` to the model and edit form, `profileViews` counter (incremented on visits by others), a six-tile stat row (chats · groups · shared · media · stories · views), a badge row (verified, admin, contact, shared groups, views), and About rows for work, local time in the owner's zone, username copy, first-joined date and shared groups. |
| **Stories were a flat grid** | No ordering, no author grouping, no insight into your own story, no keyboard shortcuts. | Unseen-first ordering with seen stories dimmed, author rail with rings, `Mine` filter, refresh action, keyboard `N` (new) / `R` (refresh), and an insights strip on "My story" (views · reactions · replies · time to expiry). Viewer already had ←/→/Esc, mute, save and the viewers list. |
| **No offline story at all** | If the API was down the app showed an empty chat list and messages failed silently. | New offline layer: IndexedDB cache (chats + messages), an outbox that queues messages composed offline and replays them on `online`, honest "queued"/"failed" statuses, and an `OfflineBanner` in the app shell. |
| **No local backup** | The only backup path was Mongo documents written by the client (`POST /api/backup` with the whole payload in the body). | Added a **SQLite mirror** (`node:sqlite`, one `.db` file per user) with snapshot/download/export/import/delete endpoints plus offline read endpoints, and a `/backup` dashboard that also exports/restores the browser cache. | --- | --- | --- |

### 0.3 Still recommended

Everything from §1.2 stands. Round 5 adds:

| # | Area | Recommendation | Why |
| --- | --- | --- | --- |
| 13 | **Envelope** | 290 routes still have no client caller; the 65 `gb-settings`, 19 `appearance` and 17 `chat-settings` endpoints are the biggest clusters. | Either surface them in Settings or delete them — see `ENDPOINT_AUDIT.md`. |

## 0.4 Background jobs (round 4)

The cron jobs used to live inside the API process, so every replica ran them and
duplicate work followed. Now:

| Piece | Behaviour |
| --- | --- |
| `server/config/redis.js` → `acquireLock(key, ttlMs)` | `SET NX PX` leader lock. No Redis ⇒ always `true` (single node needs no coordination). TTL-expiring, so a crashed node cannot deadlock the rest. |
| `services/schedulerService.js` | Started by the API only when `SCHEDULER_ENABLED !== "false"` **and** Mongo is up; every tick takes the `scheduler` lock (55 s). |
| `services/worker.js` (`npm run worker`, `--once`) | Story expiry, scheduled channel posts (atomic claim, never published twice), 30-day notification pruning, stale-call cleanup. Any number of workers is safe. |
| `docker-compose.yml` | Adds a `worker` service; API replicas get `SCHEDULER_ENABLED=false`. |

Not yet done (recommended): move the 60-s cron to BullMQ with a Redis queue so
failed jobs retry with backoff instead of waiting for the next tick.

## 1. What the review found

### 1.1 ✅ Fixed in this round

| Finding | Detail | Fix |
| --- | --- | --- |
| **Scheduled messages were unreachable** | `POST /api/messages/schedule`, `GET /api/messages/schedule` and `POST /api/messages/cancel-schedule` were declared *after* `POST/GET /:chatId`, so Express matched `"schedule"` as a chat id. Scheduling could never work. | Literal routes moved above the parameterised ones; the audit script now fails loudly on any such shadowing (`shadowed: 0`). |
| **Channel scheduler was fake** | `ChannelsPage` kept `scheduledPosts` in local state only, with `channelId="current-channel"`. | Real queue: `Channel.scheduledPosts`, publish/cancel endpoints, lazy publisher (`publishDueScheduledPosts`) that promotes due entries atomically so a post is never sent twice, plus channel picker + API wiring in the UI. |
| **Story highlights were device-local** | Highlights were `localStorage` only, so they vanished on another device and were invisible to others. | New `StoryHighlight` model + `GET/POST/PATCH/DELETE /api/stories/highlights`; the page uses the API and keeps the localStorage copy purely as an offline cache. |
| **"Import groups" / "Group settings" were toasts** | Two More-options entries only said "not available yet". | `POST /api/groups/import` (bulk create from a CSV-ish list, resolving phone/email/id) and `GET/PUT /api/groups/preferences` (who can add me, auto-mute, large-group archiving, threshold, notification + announcement defaults) with real modals. |
| **Token stored in two places** | 18 call sites read `localStorage['token']`, while zustand persisted the JWT inside `auth-storage`; any code path that wrote one and read the other lost the `Authorization` header. | Single `lib/token.js` (`getToken`/`setToken`/`setRefreshToken`/`clearTokens`/`authHeader`) used by the axios interceptor, the socket handshake, the auth store and every component that used to read storage directly. Logout now clears both copies. |
| **Bottom nav was thin** | Mobile tab bar missed contacts and profile; the home list had no icon shortcuts. | Five-item tab bar (Chats · Stories · Calls · Contacts · Settings) plus the six-icon home strip (new chat, stories, calls, groups, contacts, starred). |

### 1.2 ⚠️ Recommended next (not done yet)

Ordered by value ÷ effort. Nothing here is a security emergency; the API is
fully behind `protect` and rate limited.

| # | Area | Recommendation | Why |
| --- | --- | --- | --- |
| 1 | **Response envelope** | 396 `res.json` calls, only 74 of them return `{ success: … }`. Standardise on `{ success, data, meta }` (client already tolerates both shapes). | Removes the `data.user \|\| data` style guessing in ~20 components and makes pagination metadata possible. |
| 2 | **Pagination** | Only 4 controllers use `.skip()`; groups, contacts, calls, notifications and channels return everything. Add `?page&limit&cursor` with `{ meta: { page, total } }`. | A user with 5k chats/messages currently gets a multi-MB response. |
| 3 | **Duplicate aliases** | `PUT` + `PATCH` are registered for the same handler in several routers (`/channels/:id`, `/groups/:id`, `/privacy/settings`). | Harmless but doubles the surface to secure and document; keep one verb. |
| 4 | **Dead server surface** | 293 routes have no client caller — e.g. 65 `gb-settings` endpoints, 19 `appearance`, 17 `chat-settings`. Either wire them into Settings or mark them `@experimental`/remove. | Every unused route is API surface + tests + attack area for free. |
| 5 | **Validation** | Handlers destructure `req.body` directly. Adopt `zod` schemas per route (`validate(schema)` middleware). | Prevents `undefined` writes and makes 400s consistent. |
| 6 | **Idempotency** | `POST /messages/:chatId` has no `clientId` support. | Offline/reconnect retries can duplicate messages today. |
| 7 | **Push notifications** | `pushSubscription` is stored on the user but nothing sends Web Push; offline recipients only see the notification on next socket connect. | `web-push` + the existing gRPC `Notification.Send` fan-out would close the loop. |
| 8 | **Observability** | No request metrics/tracing. `/api/system/info` covers process state only. | Add `pino` + `/metrics` (prom-client) so rate-limit hits and 5xx rates are visible before users report them. |
| 9 | **Tests** | No automated API tests in the repo. | Supertest + an in-memory Mongo (`mongodb-memory-server`) around the 117 client-used routes would lock in today's contracts. |
| 10 | **Media lifecycle** | Cloudinary assets are never deleted when a message/story/avatar is removed. | Storage cost + GDPR deletion requests. |
| 11 | **Group calls** | Server models 1:1 calls only; the UI hides group calls. | Either extend `Call` to N participants (SFU needed beyond ~4) or document the limitation in-product. |
| 12 | **E2EE claims** | The profile page states "end-to-end encrypted chats"; transport is TLS and payloads are stored server-side. | Either implement E2EE (Signal protocol) or reword to "transport encrypted" — today the copy over-promises. |

## 3. Reproducing the review

```bash
node scripts/audit-endpoints.mjs          # rewrites docs/ENDPOINT_AUDIT.md
node scripts/audit-endpoints.mjs --stdout # full report in the terminal
npm run check:endpoints                   # CI guard: every client call has a route
```

The audit script is read-only apart from the report it writes; it parses
`server/index.js` mounts, every file in `server/routes`, and every
`api.get/post/put/patch/delete(...)` call in `client/src`.
